What I Learned:
This video focused on organizing and managing local users and groups in RHEL, with a strong focus on security and controlling access to the system.
One of the important areas introduced was the /etc directory. This directory contains many system configuration files, including files that store information about local users and groups. Understanding these files helps explain how Linux manages accounts and permissions.

The /etc Directory
The /etc directory contains important system-wide configuration files.
When working with users and groups, some of the relevant files include:
•	/etc/passwd — Contains information about local user accounts.
•	/etc/group — Contains information about local groups.
•	/etc/shadow — Stores securely protected password-related information.
These files are part of how Linux keeps track of users, groups, and account information.

Using sudo
I have used sudo many times before, but this lesson helped me understand what it actually means and why it is used.
sudo stands for "superuser do" and allows an authorised user to perform commands with elevated administrative privileges.
For example:
sudo useradd alice
Creating users and making other system-level changes generally requires administrative privileges.
Using sudo is also important from a security perspective. Instead of working as the root user all the time, a normal user can temporarily use elevated privileges only when they are needed. This helps reduce the risk of accidentally making changes that could affect the entire system.

Creating Users
A new local user can be created using:
sudo useradd username
For example:
sudo useradd alice
A password can then be assigned to the user with:
sudo passwd alice
This creates the account and allows the user to have their own identity and permissions on the system.

User IDs and Why Accounts Should Not Simply Be Deleted
An important security concept I learned was related to user IDs (UIDs).
Linux identifies users internally using a numeric UID. The username is what we normally see, but the UID is what the system uses to identify ownership of files and other resources.
Because of this, deleting a user can have security implications.

If a user account is deleted and a future user is assigned the same UID, files owned by the previous user could potentially appear to belong to the new user from the system's perspective.
This is why it can be safer in some situations to lock an account instead of deleting it, especially when the user's files and ownership information still need to be preserved.

A user account can be locked with:
sudo usermod -L username
This disables the account's ability to authenticate while preserving the account and its UID.
Modifying Users with usermod

The usermod command is used to modify an existing user account.
For example, I can use it to change a user's group membership or lock an account.
One example is adding a user to a supplementary group:
sudo usermod -aG groupname username
The options mean:
•	-a — Append the user to the group without removing existing supplementary group memberships.
•	-G — Specify the supplementary group or groups.
The -a option is important when adding a user to a group because leaving it out can replace the user's existing supplementary group memberships.

The wheel Group
I also learned about the wheel group, which is commonly used on RHEL systems for users who are trusted to perform administrative tasks through sudo.
For example:
sudo usermod -aG wheel username
Adding a user to the wheel group can give that user the ability to use sudo, depending on the system's sudo configuration.
This means that membership in wheel should be given to users who are trusted with administrative access.

Creating Groups
Groups allow multiple users to be organised together and given shared access to resources.
A new group can be created using:
sudo groupadd developers
A user can then be added to the group:
sudo usermod -aG developers username
Groups are useful because permissions can be managed for a group instead of having to configure access for every individual user separately.

Checking User and Group Information
I also learned how to check which groups a user belongs to.
The id command provides information about a user's UID, primary group, and supplementary groups:
id username
For example:
id alice
This allows me to see the user's identity and the groups associated with their account.
I can also use:
groups username
to see the groups that a particular user belongs to.

Identity Management (IdM)
The lesson also introduced the concept of Identity Management (IdM).
IdM provides a centralised way of managing identities such as users, groups, authentication, and access across systems.
Instead of manually creating and managing every user account separately on every Linux server, an organisation can use an identity management system to centralise this information and make it easier to manage access consistently.
We did not go deeply into IdM in this lesson, but I learned why it becomes useful in larger environments where many users and systems need to be managed.
